# Серверная часть

Место для реализации SB-5. Исполняемый каркас пока не создан.

По [SB-5](https://linear.app/ekaterina-rogozinnikova/issue/SB-5/karkas-bekenda-m) сервер использует FastAPI, PostgreSQL, SQLAlchemy и миграции Alembic. Docker Compose должен поднимать сервер и базу командой `docker compose up`, а `/health` — возвращать `ok`.

## Запланированные части

- SB-6: регистрация (имя, email, пароль), вход, текущий пользователь; bcrypt и JWT.
- SB-11: группы, участие и коды приглашения; роли владельца и участника, проверка прав на каждом эндпоинте.
- SB-15: вопросы и ответы, серверные фильтры, пагинация; вопрос отмечает решённым только его автор.
- SB-18: загрузка, список, скачивание и удаление файлов автором. Типы: pdf, docx, pptx, png, jpg. Хранение в отдельной папке на сервере.
- SB-20: WebSocket-сервер для Yjs, проверка токена, сохранение документов в базе; API списка и создания конспектов.
- SB-23: встречи группы, ближайшие встречи пользователя, отметки «приду».
- SB-26: pytest для авторизации и прав в группах.
- SB-28: последующее развёртывание приложения, доступного с телефона по ссылке.

Точные API-маршруты (кроме `/health`), форматы запросов и ошибок, версии библиотек и лимит размера файла нужно согласовать при реализации. В SB-20 `y-websocket` приведён как пример, конкретный WebSocket-сервер ещё предстоит выбрать.

После реализации добавьте проверенные команды установки и запуска, переменные окружения, подготовку базы данных и описание API.

Полные критерии задач: [план проекта](../docs/REQUIREMENTS.md).
