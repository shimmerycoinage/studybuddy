# Как работаем над StudyBuddy

## Задачи и ветки

Задачи и договорённости ведём в Linear. Перед началом работы назначьте задачу на себя, чтобы двое участников не делали одно и то же.

Для каждой задачи создавайте отдельную ветку от актуальной `main`:

```bash
git switch main
git pull --ff-only
git switch -c feature/SB-3-frontend-scaffold
```

Используйте `feature/` для новой функциональности, `fix/` для исправлений и `docs/` для документации. В названии оставляйте номер задачи Linear. Пример названия коммита: `SB-3: добавить каркас фронтенда`.

## Pull request

1. Отправьте свою ветку в GitHub.
2. Откройте pull request с основной веткой `main`.
3. Заполните шаблон: задача Linear, изменения, способ проверки.
4. Если меняется интерфейс, приложите изображение результата. Макеты пока не созданы; после их появления добавляйте ссылку при необходимости.
5. Попросите другого участника проверить изменения.
6. Исправьте замечания, получите минимум одно одобрение и объедините изменения.

Автор не одобряет собственный pull request. Пока остальных участников нет в репозитории, не считайте этот этап проверки выполненным.

## Перед проверкой

- Изменения соответствуют задаче, описаны ограничения и оставшаяся работа.
- Проверен затронутый сценарий; в pull request приведены результаты.
- После появления средств проверки выполнены подходящие команды сборки, линтера и тестов.
- В коммитах нет паролей, токенов, локальных `.env` и пользовательских данных.
- Инструкция запуска обновлена, если изменился запуск проекта.

## Основная ветка

После первоначальной загрузки репозитория работаем с `main` через pull request. Требование задачи SB-2 — одно одобрение и защита основной ветки. Правило в этом документе само по себе не включает защиту в GitHub: её нужно настроить отдельно по [чек-листу](docs/GITHUB_SETUP.md).
