# Исходные требования и состояние подготовки

Источник: [Linear, команда StudyBuddy (SB)](https://linear.app/ekaterina-rogozinnikova/team/SB/projects/all).

Прочитана часть задач через интерфейс Linear. Полное содержимое всех задач ещё не проверено. Этот документ фиксирует только увиденное и уточнения команды; он не заменяет Linear.

## Подтверждено из прочитанных задач

| Задача | Требования |
| --- | --- |
| SB-1 — Стек проекта | Задача отмечена Done. В прочитанном описании есть предложение обсудить и выбрать стек, но результат выбора не записан. |
| SB-2 — Репозиторий и правила | Репозиторий GitHub, доступ команды, защита `main`: только pull request и одно одобрение. Шаблон pull request и README с названием проекта и ссылкой на макеты. |
| SB-3 — Каркас фронтенда | Vite с несколькими HTML-страницами: вход, регистрация, группы. React подключается для интерактивных частей — вопросов и редактора. ESLint и Prettier. Каталоги `pages`, `components`, `api`, `hooks`, `styles`. Критерий готовности — `npm run dev` запускает приложение с тремя заглушками страниц и переходами. |
| SB-4 — Дизайн-токены и шрифт | Цвета, размеры текста, скругления и отступы вынести в CSS-переменные из раздела «Токены» спецификации. Шрифт Onest. Значения токенов и сама спецификация пока не получены. |
| SB-7 — Экраны входа и регистрации | Две формы, проверка email и длины пароля, ошибки сервера рядом с полями, состояние загрузки кнопки, работа с реальным API и управление с клавиатуры. |

## Разделы, видимые в списке проектов

1. Подготовка.
2. Регистрация и вход.
3. Общие компоненты.
4. Группы и участники.
5. Вопросы и ответы.
6. Материалы.
7. Совместные конспекты.
8. Онлайн-встречи.
9. Финал.

В списке также видны задачи по серверному каркасу, API регистрации, групп, вопросов и загрузки файлов, UI-kit, общему каркасу страниц, авторизации, конспектам и встречам. Их подробные требования ещё нужно прочитать.

## Уточнения команды

- Проект в самом начале, в команде три человека.
- Макетов пока нет: ссылку в README добавим после их создания.
- Двух остальных участников GitHub добавим позже.

## Что не определяем без оставшихся требований

- Серверный язык, фреймворк, база данных и способ авторизации.
- API-контракты, схемы данных и внешние сервисы встреч и совместного редактирования.
- Точные значения дизайн-токенов.
- Команды сборки, тестов и запуска, пока соответствующие каркасы не реализованы и не проверены.
