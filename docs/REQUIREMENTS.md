# План и требования StudyBuddy

Источник: [Linear, команда StudyBuddy (SB)](https://linear.app/ekaterina-rogozinnikova/team/SB/projects/all). Прочитаны описания всех 29 задач из девяти разделов. Снимок на 26 октября 2026 года; текущие статусы, исполнители и обсуждения остаются в Linear.

Ниже сохранены описания задач и критерии готовности. Упоминания макетов и спецификации в задачах — требования к будущей работе: по уточнению команды макетов пока нет, значения дизайн-токенов не предоставлены.

## Подготовка

### [SB-1 — Стек проекта (все трое, S)](https://linear.app/ekaterina-rogozinnikova/issue/SB-1/stek-proekta-vse-troe-s)

Обсудить и выбрать стек проекта

### [SB-2 — Репозиторий и правила (S)](https://linear.app/ekaterina-rogozinnikova/issue/SB-2/repozitorij-i-pravila-s)

Создать репозиторий на GitHub, добавить всех. Настройте защиту ветки main (только через pull request, одно подтверждение). Добавьте шаблон описания pull request и файл README.md с описанием проекта. Готово, когда: main защищена, у всех есть доступ, в README есть название и ссылка на макеты.

### [SB-3 — Каркас фронтенда (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-3/karkas-frontenda-m)

Создать проект на Vite с несколькими HTML-страницами (вход, регистрация, группы) и подключить React только там, где нужна интерактивность: вопросы и редактор. Подключить ESLint и Prettier. Сделать структуру папок: pages, components, api, hooks, styles. Готово, когда: npm run dev запускает пустое приложение с тремя заглушками страниц и переходами между ними.

### [SB-4 — Дизайн-токены и шрифт (S)](https://linear.app/ekaterina-rogozinnikova/issue/SB-4/dizajn-tokeny-i-shrift-s)

Вынести все цвета, размеры текста, скругления и отступы из раздела «Токены» спецификации в CSS-переменные. Подключить шрифт Onest. Готово, когда: в стилях нет цветов, записанных вручную, всё берётся из переменных.

### [SB-5 — Каркас бэкенда (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-5/karkas-bekenda-m)

Создать проект на FastAPI, подключить PostgreSQL через SQLAlchemy и миграции Alembic. Написать docker-compose.yml, который поднимает сервер и базу одной командой. Добавить тестовый эндпоинт /health. Готово, когда: после docker compose up по адресу /health приходит ответ ok.

## Регистрация и вход

### [SB-6 — API регистрации и входа (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-6/api-registracii-i-vhoda-l)

Эндпоинты регистрации (имя, email, пароль), входа и получения текущего пользователя. Пароли хранить только в виде хеша (bcrypt). Выдавать JWT-токен. Валидировать данные и возвращать понятные ошибки. Готово, когда: нельзя зарегистрироваться с занятым email, неверный пароль даёт ошибку, токен открывает защищённые эндпоинты.

### [SB-7 — Экраны входа и регистрации (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-7/ekrany-vhoda-i-registracii-l)

Две страницы с формами, валидация на лету (формат email, длина пароля), сообщения об ошибках с сервера, состояние загрузки на кнопке. Дизайн экранов в макете. Готово, когда: форма работает с реальным API, ошибки видны рядом с полями, форма управляется с клавиатуры.

### [SB-8 — Контекст авторизации и защищённые страницы (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-8/kontekst-avtorizacii-i-zashishyonnye-stranicy-m)

Хранить токен, добавить его в запросы, делать выход. Страницы групп доступны только после входа, иначе перенаправление на вход. Готово, когда: после обновления страницы пользователь остаётся авторизованным, выход очищает токен.

## Общие компоненты

### [SB-9 — UI-kit (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-9/ui-kit-l)

Собрать компоненты из спецификации: Button (Primary, Secondary, Pill), Input, Avatar, StatusChip, Tabs. Все состояния, понятные пропсы. Кнопку и поле нужно уметь использовать и в обычном HTML, поэтому сделать для них общие CSS-классы. Готово, когда: на отдельной странице /ui виден каждый компонент во всех вариантах, и они совпадают с макетом.

### [SB-10 — Sidebar и общий каркас страниц (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-10/sidebar-i-obshij-karkas-stranic-m)

Боковое меню на 240 px с пятью пунктами и подсветкой текущего, основная область с отступами из спецификации. Готово, когда: переключение пунктов меняет страницу, активный пункт подсвечен.

## Группы и участники

### [SB-11 — API групп (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-11/api-grupp-l)

Модели группы и участия. Создание, список моих групп, детали, вступление по коду приглашения, выход, удаление участника владельцем. Роли: владелец, участник. Проверка прав на каждом эндпоинте. Готово, когда: участник не может удалять других, владелец может, группа возвращает число участников.

### [SB-12 — Экран «Мои группы» (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-12/ekran-moi-gruppy-l)

Сетка GroupCard и пунктирная карточка «Нет своей группы?», блок «Ближайшие встречи» справа. Состояния: загрузка, пустой список, ошибка. Готово, когда: экран совпадает с макетом, сетка перестраивается при сужении окна.

### [SB-13 — Создание и вступление в группу (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-13/sozdanie-i-vstuplenie-v-gruppu-m)

Модальные окна: создать группу (название, описание) и вступить по коду. Готово, когда: после создания группа сразу появляется в списке, неверный код показывает ошибку.

### [SB-14 — Управление участниками (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-14/upravlenie-uchastnikami-m)

Список участников группы с ролями, кнопка копирования кода приглашения, удаление участника для владельца. Готово, когда: обычный участник не видит кнопок удаления, после удаления список обновляется.

## Вопросы и ответы

### [SB-15 — API вопросов и ответов (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-15/api-voprosov-i-otvetov-l)

Создание вопроса в группе, список с фильтрами (все, без ответа, решённые), ответы, отметка «решён» (только автор вопроса). Пагинация. Готово, когда: фильтры работают на сервере, ответы приходят вместе с автором и временем.

### [SB-16 — Страница группы и список вопросов ( L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-16/stranica-gruppy-i-spisok-voprosov-l)

Заголовок, вкладки, фильтры-пилюли, QuestionItem в трёх вариантах, кнопка «Задать вопрос» с формой. Готово, когда: фильтры меняют список, новый вопрос появляется без перезагрузки страницы.

### [SB-17 — Страница вопроса (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-17/stranica-voprosa-m)

Текст вопроса, список ответов, форма нового ответа, кнопка «Отметить решённым» для автора. Готово, когда: чипы статуса обновляются сразу, кнопку видит только автор.

## Материалы

### [SB-18 — API загрузки файлов (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-18/api-zagruzki-fajlov-l)

Загрузка файла в группу (ограничение размера и типов: pdf, docx, pptx, png, jpg), список, скачивание, удаление автором. Файлы хранятся на диске сервера в отдельной папке. Готово, когда: загрузить большой файл или запрещённый тип нельзя, скачивание отдаёт исходный файл.

### [SB-19 — Вкладка «Материалы» (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-19/vkladka-materialy-l)

Список файлов с иконкой типа, размером и автором, загрузка перетаскиванием и кнопкой, индикатор прогресса, скачивание. Готово, когда: ошибки загрузки показываются понятным текстом, список обновляется после загрузки.

## Совместные конспекты

### [SB-20 — Сервер совместного редактирования (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-20/server-sovmestnogo-redaktirovaniya-l)

Поднимите websocket-сервер для Yjs (например, y-websocket или аналог на Python), сохраняйте документы в базу, проверяйте права по токену. API списка и создания конспектов в группе. Готово, когда: два браузера видят правки друг друга за секунду, после перезапуска сервера текст не теряется.

### [SB-21 — Редактор конспекта (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-21/redaktor-konspekta-l)

TipTap + Yjs, панель EditorToolbar (заголовок, жирный, курсив, список), оформление EditorPaper по спецификации. Список конспектов группы на вкладке «Конспекты». Готово, когда: две вкладки браузера редактируют один текст без конфликтов, панель работает с клавиатуры.

### [SB-22 — Присутствие и комментарии (L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-22/prisutstvie-i-kommentarii-l)

Показывать аватары тех, кто редактирует сейчас, и цветные курсоры. Комментарии к выделенному фрагменту: список справа, форма ответа. Готово, когда: при выходе человека аватар пропадает, комментарий привязан к фрагменту и виден всем.

## Онлайн-встречи

### [SB-23 — API встреч (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-23/api-vstrech-m)

Создание встречи (название, время), список встреч группы и ближайшие встречи пользователя, отметка «приду». Готово, когда: прошедшие встречи не попадают в ближайшие, число «придут» считается правильно.

### [SB-24 — Вкладка «Встречи» и видеокомната ( L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-24/vkladka-vstrechi-i-videokomnata-l)

## Финал

### [SB-25 — Адаптив ( L)](https://linear.app/ekaterina-rogozinnikova/issue/SB-25/adaptiv-l)

Проверить все экраны на ширинах 375, 768 и 1280. На телефоне боковое меню превращается в нижнюю панель. Макеты мобильной версии в документах. Готово, когда: на ширине 375 нет горизонтальной прокрутки, всё нажимается пальцем.

### [SB-26 — Тесты (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-26/testy-m)

Тесты на pytest для авторизации и прав в группах. Для фронтенда тесты на Button и форму входа (Vitest). Готово, когда: тесты запускаются одной командой и проходят.

### [SB-27 — Документация пользователя (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-27/dokumentaciya-polzovatelya-m)

Раздел «Запуск проекта» для разработчиков пишет бекенд разработчик. Готово, когда: человек без подготовки пройдёт всё по инструкции и ни разу не застрянет.

### [SB-28 — Деплой (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-28/deploj-m)

Развернуть приложение на любом бесплатном или дешёвом хостинге, чтобы им можно было пользоваться по ссылке. Готово, когда: приложение открывается по ссылке с телефона.

### [SB-29 — Демо и защита (M)](https://linear.app/ekaterina-rogozinnikova/issue/SB-29/demo-i-zashita-m)

Сценарий показа на 5–7 минут, тестовые данные (группа, вопросы, конспект, встреча). Каждый рассказывает о своей части.

## Уточнения и открытые решения

- В команде три человека. Двух остальных участников GitHub добавим позже по решению пользователя.
- Макетов пока нет. Ссылку в README добавим после их создания; фразы о готовых макетах в исходных задачах не подтверждают их наличие.
- SB-1 отмечена Done, но результат выбора стека не записан в её описании. Технические требования берём из конкретных задач SB-3, SB-5, SB-6, SB-20, SB-21, SB-24 и SB-26.
- До реализации нужно согласовать API-контракты, версии зависимостей, лимит загрузки файлов, значения дизайн-токенов, WebSocket-сервер для Yjs и площадку размещения.
- Команды сборки, запуска и тестов следует добавлять в инструкции после реализации и проверки каркасов, а не считать их уже доступными.
