# StudyBuddy

Учебный командный проект для совместной учёбы. Команда состоит из трёх человек; проект находится на начальном этапе.

Репозиторий: [shimmerycoinage/studybuddy](https://github.com/shimmerycoinage/studybuddy). Доступ закрытый (Private), основная ветка — `main`.

## Команда

Каждый участник заполняет свою строку под своим аккаунтом GitHub.

| № | Имя и фамилия | Роль в проекте |
| --- | --- | --- |
| 1 | Логинова Анна | фул стек |
| 2 | Подмогаев Дмитрий  | Бэкенд |
| 3 | _Укажите имя_ | _Укажите роль_ |

## Возможности по плану Linear

- Регистрация и вход.
- Учебные группы и управление участниками.
- Вопросы и ответы внутри групп.
- Учебные материалы.
- Совместные конспекты.
- Онлайн-встречи.

Это план разработки, а не список реализованных функций. Приложение пока не реализовано в этом репозитории.

## Структура

```text
.github/             Шаблон pull request
backend/             Место для серверной части
docs/                Известные требования и настройка GitHub
frontend/            Место для клиентской части
CONTRIBUTING.md      Правила совместной работы
```

В одной папке храним клиентскую и серверную части, чтобы команда работала с общей документацией и согласовывала изменения через один репозиторий.

## Стек по задачам Linear

| Часть | Технологии и требования |
| --- | --- |
| Клиент | Vite, несколько HTML-страниц; React для интерактивных вопросов и редактора; ESLint и Prettier |
| Сервер | FastAPI, PostgreSQL, SQLAlchemy, миграции Alembic |
| Локальный запуск | Docker Compose для сервера и базы; проверка `/health` |
| Авторизация | JWT; хеширование паролей bcrypt; проверка прав на сервере |
| Конспекты | TipTap + Yjs; WebSocket-сервер с сохранением документов и проверкой доступа |
| Видеовстречи | Jitsi Meet, комната по идентификатору встречи |
| Проверки | pytest для авторизации и прав; Vitest для Button и формы входа |
| Оформление | Шрифт Onest; CSS-переменные для дизайн-токенов |

Технологии перечислены по требованиям; зависимости и код ещё не добавлены. Все 29 задач с критериями готовности и ссылками: [план проекта](docs/REQUIREMENTS.md).

## Запуск

Команд запуска пока нет: в репозитории подготовлены только документы и структура. После реализации каркасов SB-3 и SB-5 сюда нужно добавить проверенные шаги установки и запуска, переменные окружения и требования к версиям инструментов.

## Совместная работа

1. Выбрать задачу в Linear и назначить её на себя.
2. Создать отдельную ветку, например `feature/SB-3-frontend-scaffold`.
3. Внести изменения и открыть pull request в `main`.
4. Получить одобрение другого участника и объединить изменения.

Подробности: [правила команды](CONTRIBUTING.md). Настройка доступа и защиты `main`: [чек-лист GitHub](docs/GITHUB_SETUP.md).

Двух остальных участников добавим позже. Техническая защита `main` не действует: GitHub подтвердил ограничение текущего тарифа для Private-репозитория. Пока правило про pull request и одно одобрение — договорённость команды. Интеграция GitHub с Linear пока не настроена.

## С чего начать

1. Выполнить каркасы [SB-3 — клиент](https://linear.app/ekaterina-rogozinnikova/issue/SB-3/karkas-frontenda-m) и [SB-5 — сервер](https://linear.app/ekaterina-rogozinnikova/issue/SB-5/karkas-bekenda-m).
2. Подготовить макеты и значения дизайн-токенов для SB-4 и UI-kit.
3. Согласовать API-контракты и реализовать регистрацию и вход (SB-6–SB-8).
4. Перейти к группам, вопросам, материалам, конспектам и встречам по [плану Linear](docs/REQUIREMENTS.md).

Это рекомендуемый порядок начала работы, а не изменение назначений и статусов задач в Linear.
